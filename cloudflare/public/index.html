Office Air Quality Monitor

Real-time Indoor Air Quality Monitoring System

The Smart Air Quality & Carbon Monitor is an IoT-based environmental monitoring system designed for offices, schools, and indoor spaces. It continuously measures particulate matter (PM1.0, PM2.5, PM4.0, PM10), carbon dioxide concentration (CO₂), and temperature & humidity in real-time. Data is transmitted wirelessly to a cloud dashboard over Wi-Fi using HTTPS, enabling remote monitoring, AQI calculation per EPA standards, and historical trend analysis.

📡 Communication Protocols
UART
Sensor ↔ ESP32

UART (Universal Asynchronous Receiver-Transmitter) is used for serial communication between all sensors and the ESP32. The SPS30 runs on UART2 at 115200 baud for high-speed PM data transfer, while the CO2-C8 uses UART1 at 9600 baud with a custom Modbus-like query/response protocol (5-byte command, 14-byte response with CRC16 checksum).

HTTPS
ESP32 → Cloud Server

Sensor data is serialized into JSON format and transmitted to the AITALIM IoT Dashboard via HTTPS POST requests over Wi-Fi (802.11 b/g/n). The ESP32 uses WiFiClientSecure with TLS encryption. Data is posted to /api/data.php?device_id=air_quality_node_01 every 5 seconds.

JSON
Data Payload Format

Each transmission contains calibrated readings in a compact JSON payload:

{"pm1_0":12.5, "pm2_5":18.3, "pm4_0":22.1, "pm10":25.7, "co2_ppm":485, "temperature":24.3, "humidity":55.2}
1-Wire
DHT22 → ESP32

The DHT22 uses a proprietary single-wire digital protocol on GPIO 4. A 10kΩ pull-up resistor between VCC (3.3V) and the DATA pin is required. The ESP32 sends a start signal (pull low for 1ms), then the DHT22 responds with 40 bits (16-bit humidity + 16-bit temperature + 8-bit checksum).

🏗️ System Architecture
🔬 Calibration & Data Processing
1
30-Second Warm-up (SPS30)

Per the Sensirion datasheet, the SPS30 requires a minimum 30-second warm-up after power-on before readings are reliable. All PM readings during this period are discarded. A fan cleaning cycle also runs at startup to clear condensation from optics.

2
Hänel Humidity Compensation

The SPS30 has no built-in humidity correction. When RH exceeds 75%, water condenses on particles causing them to swell, inflating readings. We apply the Hänel hygroscopic growth correction:
corrected = raw / (1 + 0.24 × RH / (100 − RH))

3
Physical Constraint Enforcement

PM values are cumulative: PM10 ≥ PM4.0 ≥ PM2.5 ≥ PM1.0 must always hold. If the sensor returns a smaller bin with a higher value (measurement artifact), the ordering is corrected. Values are clamped to the 0–1000 µg/m³ measurable range.

4
EMA Smoothing (α = 0.3)

An Exponential Moving Average filter is applied to all PM channels. With α=0.3, each new reading contributes 30% while the previous smoothed value retains 70%, eliminating sensor jitter while still responding to real air quality changes within 5–7 readings.

5
CO₂ Baseline Clamping (400 ppm)

Per the CO2-C8 datasheet, the sensor range is 400–5000 ppm with ±50ppm ±3% accuracy. Atmospheric CO₂ baseline is ~420 ppm; any reading below 400 is physically impossible and clamped. Readings above 5000 are capped at the sensor's maximum.

⚠️ Limitations & Engineering Considerations
⚡
Power Consumption Constraints

The system requires a constant 5V power source capable of delivering at least 1A. The SPS30 fan and CO2-C8 NDIR heating element draw significant current (up to 80mA and 150mA peak respectively). Battery operation is generally unfeasible for long-term continuous monitoring without a substantial lithium-ion pack or solar array.

💤
Sleep Mode Incompatibility

While the ESP32 supports deep sleep to conserve energy, the SPS30 requires continuous power to run its auto-cleaning cycles, and the CO2-C8 requires extensive warm-up times. Constantly waking the sensors from sleep drastically degrades data quality and reduces the lifespan of the optical/heating components. Thus, the system is designed strictly for "always-on" mains power operation.

🌡️
Sensor Thermal Drift

The ESP32-WROOM-32 can generate considerable heat when Wi-Fi is actively transmitting. If the DHT22 temperature sensor is placed too close to the ESP32 or the LM2596 converter in a closed enclosure, it will suffer from thermal drift, reading artificially high temperatures and causing the humidity to read artificially low. Proper ventilation and physical isolation in the chassis design is mandatory.
